# issue 草案: 国税庁の索引から消えた文書が、現行の文書と区別できないまま検索に出る

対象リポジトリ: houki-nta-mcp（2026-09-12 作成）
提出先: https://github.com/shuji-bonji/houki-nta-mcp/issues
タイトル案: 索引から消えた文書に印を付け、応答で区別できるようにする

---

## 保持そのものは正しい設計です

bulk download を再実行すると、`computeBulkAggregation` が 4 つに分類します。

| 分類 | 意味 |
| --- | --- |
| `newDocs` | 索引にあって DB に無かった |
| `updatedDocs` | 両方にあり `content_hash` が変わった |
| `orphanedDocs` | **DB にあるが索引から消えた** |
| `movedDocs` | orphaned と new でタイトルが一致するペア（移動の推定） |

`orphanedDocs` は DB から消しません。`src/services/bulk-aggregation.ts` に理由が書かれています。

> **注意**: orphaned は DB から DELETE せず、件数だけ集計する設計（過去通達の法的価値を保持するため）。

**この方針は妥当だと考えます。** 国税庁の索引から外れても、過去の課税期間の判断では依然として意味を持つ通達があります。消してしまうと、その期間の調査ができなくなります。

## 問題は、保持していることが利用者に伝わらないことです

保持した文書に印が付きません。`document` テーブルに該当する列が無く、`orphanedDocs` は件数だけが `baseline-{doc_type}.json` の実行履歴に残ります。検索も取得も、この状態を見ません。

結果として、次のことが起きます。

- `nta_search_*` の結果に、国税庁サイトから消えた文書が**現行の文書と同じ形で**並ぶ
- `sourceUrl` を開くと 404 になる（あるいは別の内容のページに着く）
- `fetched_at` は消える前に取得した日時のままなので、`freshness` は「古い」としか言わない。「索引から消えた」とは言わない
- LLM がこれを引用すると、「現在も有効な国税庁の文書」として提示されてしまう

houki-egov-mcp には同じ問題がありません。DB には古い版も残りますが、検索が `current_revision_status = 'CurrentEnforced' OR remain_in_force = 1` で絞るためです。houki-nta-mcp には、これに当たる絞り込みがありません。

## 提案

**消さずに、印を付けて、注記付きで返す**形を推します。保持の方針を変えず、利用者が判断できる材料を足す方向です。houki シリーズの「出典を示して利用者が判断する」という立場とも合います。

### 1. `document` に列を足す

```sql
-- v6: 索引から消えたことを最初に確認した日時。NULL は索引にあることを示す
orphaned_at TEXT
```

bulk download の集計で orphaned と判定した doc_id に入れます。次の実行で索引に戻っていれば NULL に戻します（国税庁サイトの一時的な不整合や、世代ディレクトリの移行中に消えたように見える場合があるため）。

### 2. 応答で区別できるようにする

`nta_search_*` と `nta_get_*` の応答に、その文書の状態を入れます。

```jsonc
{
  "docId": "...",
  "index_status": "removed_from_index",   // 索引にあるときは付けない、または "listed"
  "orphaned_at": "2026-10-01T00:00:00Z",
  "notice": "この文書は国税庁の索引から外れています。過去の期間の判断では依然として意味を持つ場合がありますが、現在の取扱いは最新の通達で確認してください"
}
```

検索結果から除外はしません。除外すると、過去の期間を調べたい利用者が引けなくなります。

### 3. 絞り込みの引数を足すか

`nta_search_*` に「索引にあるものだけ」「消えたものだけ」を選ぶ引数を足す案もあります。**まずは印と注記だけで様子を見るのがよい**と考えます。引数を増やすと LLM 側の判断が要る箇所が増えます。

## 確認が要ること

- **現状どれだけ orphaned があるか**。`baseline-{doc_type}.json` の実行履歴に件数が残っているので、まずそこを読むのが早いです。0 件なら急ぎません
- **移動との区別**。国税庁サイトは世代ディレクトリの移行（`sozoku` → `sozoku2`、`hyoka` → `hyoka_new`）を行うため、URL が変わっただけで「消えた」ように見える場合があります。`movedDocs` の推定はタイトル一致という粗いものなので、印を付けるときに移動分を巻き込まないか確かめる必要があります

## 完了判定

- 索引から消えた文書が、検索結果で現行の文書と区別できる
- その文書が検索結果から消えていない（保持の方針を変えていない）
- 次の bulk download で索引に戻った文書は、印が外れる
- 世代ディレクトリの移行で URL が変わっただけの文書に、誤って印が付かない
