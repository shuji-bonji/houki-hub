# nta_get_tax_answer の sections が、国税庁のページの小見出し（h3）を落とし、「概要」の 1 節にまとめてしまう

## 起きていること

`nta_get_tax_answer { no: "6101", format: "json" }` の `taxAnswer.sections` が、見出し 3 つ（`概要`・`根拠法令等`・`関連リンク`）になった。小見出し「消費税の負担者」「課税のしくみ」「申告・納付」「納税事務の負担軽減措置等」の本文は `概要` の `paragraphs` に続けて入り、小見出しの文字列はどこにも入らない。

| 実測 | `fetchedAt` | `effectiveDate` | `sections[].heading` |
| --- | --- | --- | --- |
| 2026-10-04 10:00 頃 JST、plugin 0.24.0 | `2026-09-12T20:05:55.721Z` | `令和7年4月1日現在法令等` | 概要・消費税の負担者・課税のしくみ・申告・納付・納税事務の負担軽減措置等・根拠法令等・関連リンク（7 つ） |
| 2026-10-05 05:20 頃 JST、plugin 0.25.0 | `2026-10-04T03:47:44.159Z` | `令和8年4月1日現在法令等` | 概要・根拠法令等・関連リンク（3 つ） |

どちらも `source: "db"`。2 回目の行は、2026-10-04 13:30 頃 JST の `--bulk-download-everything`（0.24.0）で取り込み直したもの。

2026-10-05 JST に国税庁のページ（https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6101.htm）を見ると、見出しは次の順だった。

- h2: 対象税目・概要
- h3（「概要」の下）: 消費税の負担者・課税のしくみ・申告・納付・納税事務の負担軽減措置等
- h2: 根拠法令等・関連リンク・お問い合わせ先

## 原因の見込み

`src/services/tax-answer-parser.ts` の `extractSections()` は h2 だけで節を切り、次の h2 までの `p` / `div` / `li` を集める。h3 は集める対象に入っていないので、見出しの文字列が捨てられ、h3 の後の段落は直前の h2（概要）の節に入る。

1 回目（7 つの見出し）の行は、ページが小見出しを h2 で書いていた頃の取り込みだったと考えられる。国税庁が令和 8 年 4 月 1 日版への更新で小見出しを h3 にし、2026-10-04 の取り込みで新しい形のページを読んだ。パーサーは 0.10.0 から変わっていないので、0.24.1・0.25.0 の変更が原因ではない。前のページが h2 だったことは、取り込んだ行が上書きされたため確かめていない。

## 困ること

- 小見出しの境目が分からなくなり、「申告・納付」だけを引用する、といった使い方ができない
- `概要` の `paragraphs` に 30 段落近くが入り、どこからどこまでが何の話かを読み手が本文から推し量ることになる
- 6101 以外にも、小見出しを h3 で書いた記事は同じになる（件数は未確認）

本文の文字列そのものは落ちていない（小見出しの文字列だけが落ちる）。

## 直し方（案）

- 案 A: h3 も節の区切りにし、`sections` を平らなまま `{ heading: "消費税の負担者", paragraphs: [...] }` として並べる。7 つの見出しに戻り、今までの応答の形と同じになる。h2 と h3 の区別は失う
- 案 B: `sections[].level`（2 / 3）を足す。T4 の「足すだけ」に当たる
- 案 C: h3 を節にせず、`paragraphs` に見出しの文字列を 1 段落として入れる

勧める: 案 A（応答の形を変えずに 2026-09 までと同じ見出しに戻る）。仕様は `specs/current/nta_get_tax_answer/spec.md` の sections の項を MODIFIED にする。取り込み済みの DB の行は、投入をやり直すか、`nta_get_tax_answer` の書き戻しの規則で作り直す必要がある（`full_text` の作り方も同じ関数を使うので、検索の本文にも影響するか確かめる）。

## 確かめ方（shuji の Mac）

小見出しを h3 で書いた記事がどれだけあるかの目安:

```sql
-- ~/.cache/houki-nta-mcp/cache.db
SELECT doc_id, fetched_at FROM document
WHERE doc_type = 'tax-answer' AND full_text LIKE '%消費税の負担者%';
```

（`full_text` に小見出しの文字列が残っているかで、取り込みのときに h3 を落としているかが分かる。6101 で 0 件なら落としている）
