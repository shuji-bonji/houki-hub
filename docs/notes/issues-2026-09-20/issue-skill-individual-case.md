# 「私の場合はどうなるか」の行に手順書が無い

提出先: [houki-research-skill](https://github.com/shuji-bonji/houki-research-skill) の Issue

## いまの状態

`SKILL.md` の「問いの形 → workflow」の表で、この行だけ workflow の欄が手順書ではなく「鉄則 1 の応答型（返すもの / 返さないもの）」を指しています。

| 問いの形 | workflow | 業法の線 |
| --- | --- | --- |
| 私の場合はどうなるか（個別の事案） | 鉄則 1 の応答型 | **ここが線。** 条文・通達・論点までを返し、結論・可否・金額は返さない |

4 行のうち業法の線（税理士法 52 条 / 弁護士法 72 条 / 司法書士法 3 条 / 社労士法 27 条）が一番近いのがこの行です。ほかの 3 行には手順書があるか、予定が立っています。線に一番近い行に手順が無いのは順序が逆だと考えます。

## この行の位置づけ

法規シリーズがこの行で引き受けるのは、**士業者に相談するまでの情報整理** です。相談の代わりではありません。

利用者が士業者のところへ持って行けるように、関わる条文と、拘束力の別と、どの事実で結論が変わるかを揃えます。結論・可否・金額は、資格を持つ人が事案を見て出すものなので返しません。手順書はこの位置づけを冒頭に書き、応答の型もそこから決めます。

## 難しいところ

- **聞き取りの深さ** — 事案を細かく聞くほど当てはめに近づきます。どこまで聞いてよいかを手順に書けるか
- **返すものと返さないものの境目** — 「この事実なら 2 条 3 号に当たる」は当てはめです。「2 条 3 号は◯◯を要件にしている」は条文の説明です。この差を手順として書けるか
- **分かれ目の示し方** — 結論を書かずに役に立つには、「どの事実で結論が変わるか」を列挙する形が要ります

## 手順の骨子（案）

1. 問いが「事案の当てはめ」かどうかを見分ける（「私の場合」「うちの会社は」「この金額だと」）
2. 事案から論点を抜き出し、条文に戻す（事実を評価せず、どの条が関わるかだけを出す）
3. 条文・政令・省令・通達・Q&A を、拘束力の別を分けて並べる
4. 分かれ目を列挙する — どの事実が決まれば、どの条のどちらに転ぶか
5. 結論・可否・金額は書かない。判断が要る旨と、その分野の士業への相談を案内する

## 完了条件

- `workflows/individual-case.md`（名前は要検討）がある
- 線を越えない `examples/` を 1 本。応答に結論が混じっていないことを目で確かめる
- `SKILL.md` の表のこの行が手順書を指す
