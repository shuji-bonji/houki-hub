# [凍結] 士業者が利用者のときの業法の線の扱い

提出先: [houki-hub](https://github.com/shuji-bonji/houki-hub) の Issue

> **この Issue は着手しません。** OSS として出している範囲の外にある別機能の構想なので、記録として残すだけです。構想があることを忘れないための置き場所として使います。

## いまの決まり

`houki-research-skill` の `SKILL.md` は、こう書いています。

> workflow は **問いの形** で選ぶ。利用者が名乗る立場（エンジニア / 納税者本人 / MCP を組む開発者）では選ばない。

利用者が資格を名乗っても、応答は変わりません。

## 法規シリーズがいま引き受けている範囲

**士業者に相談するまでの情報整理** です。相談の代わりではありません。関わる条文と、拘束力の別と、どの事実で結論が変わるかまでを揃え、結論・可否・金額は返しません。

この位置づけでいる限り、利用者が誰であっても返すものは同じなので、資格による場合分けは要りません。

## 構想の中身

税理士法 52 条・弁護士法 72 条・司法書士法 3 条・社労士法 27 条が禁じているのは、**無資格者が業として** 取り扱うことです。有資格者が自分の業務で引く分には、これらの線に当たりません。そこから、資格を確かめたうえで線の位置を変える案が出ています（2026-08-25 のメモ「相談メモ + 士業ルーティング」の資格確認 3 段階）。

## なぜいま着手しないか

- 資格の確認は本人確認と結びつきます。OSS の MCP / Skill の中ではなく、それを使うサービスの側の話になります
- 自己申告だけで線を動かすと、申告するだけで結論が返る状態になります。OSS として配るものに、その分岐を入れるべきではありません
- 士業者向けの機能は、無償で配る範囲とは別の線引きになります

## 留意してほしいこと

想定利用者に士業者を数える場面（README・サイト・記事・発表）では、次の 2 点を前提にしてください。

1. skill は「有資格者は線の内側」という前提を持っていません。士業者が使っても、返ってくるのは相談前の情報整理までです
2. 資格による場合分けは、この Issue が閉じるまで実装しません
