`computeDaysSince` は、取得時刻として解釈できない文字列や、ISO 8601 以外の書き方も受け付けます。解釈できないときは `0` を返すので、`judgeStaleness` に渡すと、取得時刻が壊れていても `fresh`（新しい）と判定されます。MCP サーバーが「この文書は古いかもしれない」と利用者に伝える判定に影響します。

### いまの状態

`nowMs` はどれも `2026-05-08T00:00:00Z`。

| 入力 | `computeDaysSince` | `judgeStaleness` に渡した結果 |
|---|---|---|
| `"not-a-date"`（解釈できない） | `0` | `"fresh"` |
| 今より後の時刻 | `0` | `"fresh"` |
| `"2026/05/07"`、`"May 7, 2026"`（ISO 8601 以外） | `1` | `"fresh"` |
| `"2026-05-07T08:00:00"`（時差なし） | 実行環境の TZ が UTC なら `0`、Asia/Tokyo なら `1` | — |
| `"2026-02-30T00:00:00Z"`（存在しない日付） | `67`（3 月 2 日として数える） | `"outdated"` |
| `nowMs` に `NaN` | `NaN` | `"outdated"` |

`judgeStaleness` 単体では、負の値（`-5`、`-Infinity`）は `"fresh"`、`NaN` は `"outdated"` です。JSDoc は「負値を 0 に丸めるのは呼び出し側の責務」としています。

### 決めること

- 解釈できない取得時刻を `0` と区別できる値（例: `null` や `NaN`）で返すか、呼び出し側の責任のままにするか
- ISO 8601 以外の書き方、時差の無い時刻、存在しない日付を受け付けるか
- `judgeStaleness` が `NaN` と負の値をどう扱うか（例外、または特別な段階）
