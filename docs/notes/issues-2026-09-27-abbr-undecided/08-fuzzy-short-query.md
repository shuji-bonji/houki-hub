`findSimilar` と `suggestCorrection` は名前全体どうしの編集距離で比べます。そのため、2〜3 文字の query は意味の違う短い略称と近くなり、打ち間違いの候補として返ります。また、`suggestCorrection` は、query と一致した名前も「もしかして」の候補に入れて返します。

### いまの状態

| 呼び出し | 結果 |
|---|---|
| `findSimilar('民法')` | `民`（`民法`、距離 0）に続けて、`所法`・`法法`・`消法`・`措法`（どれも距離 1） |
| `findSimilar('法')` | `所法`・`法法`・`法令`・`法規`・`消法`（どれも距離 1） |
| `suggestCorrection('民法')` | `['民法', '所得税法', '法人税法', '消費税法', '租税特別措置法']`。先頭は query と同じ法令 |

### 決めること

- query の最短文字数を設けるか、距離を名前の長さで割るなど長さを補うか（ロードマップの設計上の課題 2「Levenshtein 単独か長さ補正か」）
- `suggestCorrection` で、query と一致したエントリを候補から外すか
- 今のままにする場合、「近い名前を返す関数で、訂正の候補とは限らない」ことを仕様と README に書くか
