# 設計メモ: 章・節単位の分割取得をどう置くか（egov#22）

対象リポジトリ: houki-egov-mcp（`houki-hub/mcp/houki-egov-mcp`、2026-09-20 JST 作成）
ブランチ: `feat/22-range-fetch`
版の案: **v0.14.0**（ツールを 1 本足すので minor）
出典: [egov#22](https://github.com/shuji-bonji/houki-egov-mcp/issues/22) / houki-hub#20 の機能 6（大きな法令の分割取得）/ houki-hub#21

---

## 1. 何が空いていたか

条文を取る道は 2 つだけでした。

| ツール | 返すもの |
|---|---|
| `get_law` | 1 条（指定すれば 1 項・1 号） |
| `get_toc` | 目次（条見出しまで。本文は返さない） |

民法の「契約」を読みたいとき、この 2 つでは「目次を引いて条番号を数え、`get_law` を 198 回呼ぶ」しかありません。逆に法令全体を返す道はなく、`law_full_text` をそのまま渡すと民法は 1.6 MB です。読みたい単位（編・章・節）で取る道が無い、というのが #22 でした。

## 2. 何をどれだけ返すことになるか

2026-09-20 に e-Gov 法令API v2 の `law_full_text` で、構造階層ごとに配下の条本文のバイト数を測りました（UTF-8 の日本語は 1 文字 3 バイト）。

| 法令 | 最上位 | 章（中央値 / 最大） | 節（中央値 / 最大） | 30 KB 超の章 |
|---|---|---|---|---|
| 民法 | 編 5（54〜193 KB） | 6.2 KB / 98.2 KB | 3.7 KB / 34.3 KB | 4 / 39 |
| 会社法 | 編 8（最大 702 KB） | 17.9 KB / 207.6 KB | 5.5 KB / 55.0 KB | 11 / 36 |
| 所得税法 | 編 6（最大 434 KB） | 10.8 KB / 229.1 KB | 10.4 KB / 167.3 KB | 5 / 27 |
| 消費税法 | 章 6（階層は章のみ） | 59.5 KB / 102.4 KB | — | 4 / 6 |
| 労働基準法 | 章 14 | 4.9 KB / 44.7 KB | — | 1 / 14 |

読み取れたこと。

- **編は大きすぎます**。民法第三編が 193 KB、会社法第二編が 702 KB です。編を丸ごと返す使い方は現実的ではありません
- **章でも足りないことがあります**。民法第三編第一章（債権総則）は 183 条・98 KB、会社法の最大の章は 207 KB です。「章を指定したら必ず 1 回で返る」とは言えません
- **節まで下りれば大半は収まります**が、消費税法・労働基準法のように節を持たない法令があります。節を必須にはできません

つまり、**範囲の指定とは別に、返す量の上限とその続きの取り方**が要ります。

## 3. 番号だけでは範囲が決まらない

`Chapter@Num` は編ごとに振り直されます。民法には `Chapter1` が 5 つ（各編の第一章）、`Section1` が 19 あります。会社法は `Section1` が 22 です。

枝番号の階層もあります（`Chapter:2_2` = 第二章の二、`Section:1_2`、`Subsection:4_2`）。所得税法・会社法・民法で見つかりました。

そのため範囲の指定は、上位の階層と組み合わせるか、根からのパスで書く必要があります。

## 4. 決めたこと

### 4-1. `get_law` に足さず、新しいツールにした

| 案 | 判断 |
|---|---|
| A. `get_law_range` を足す（11 本目） | **採用** |
| B. `get_law` に `part` / `chapter` / … を足す | 見送り |
| C. `get_toc` に「本文も返す」引数を足す | 見送り |

`get_law` は 1 条（項・号）を返すツールで、`article` を省くと目次を返す振る舞いも持っています。ここに範囲の引数を足すと、`article` との排他・`format: "toc"` との関係・上限で打ち切ったときの応答が、1 つのツールの説明に混ざります。範囲取得は応答の形（`range` / `articles` / 打ち切り）も 1 条の取得と違うので、別のツールにしました。`get_law` の description には「章・節をまとめて取るときは `get_law_range`」の 1 文を足しています。

C を採らなかったのは、`get_toc` が「目次だけを返すから安い」ツールとして使われているためです。本文を返す引数をそこに足すと、同じツールの応答サイズが 2 桁変わります。

### 4-2. 範囲の指定は 3 通り、同時には 1 つだけ

| 指定 | 書き方 | 使う場面 |
|---|---|---|
| 階層の番号 | `part: 3, chapter: 2` | 目次を見ずに、条文に書かれた「第三編第二章」から直接引く |
| パス | `path: "Part3/Chapter2"` | `get_toc` の `toc[].path` をそのまま渡す |
| 附則 | `suppl_index: 12` | `get_toc` の `suppl_provisions[].index` をそのまま渡す |

番号は `3` / `"3"` / `"三"` / `"第三編"` / `"2の2"` / `"第二章の二"` を受けます（`toEgovStructureNum()`）。上位の階層は省略でき、省略した分は絞り込みに使いません。

`chapter: 2` だけを渡して複数の章に当たったときは、**推測で 1 つを選ばず**、候補のパスを `hint` と `next_actions` に入れた `INVALID_ARGUMENT` を返します。

```jsonc
{
  "error": "指定された範囲が 5 か所あります。上位の階層も指定してください",
  "code": "INVALID_ARGUMENT",
  "hint": "該当するパス: Part1/Chapter2, Part2/Chapter2, …（Chapter@Num は編ごとに振り直されます）",
  "next_actions": [
    { "action": "get_law_range", "reason": "第三編　債権 第二章　契約", "example": { "law_name": "民法", "path": "Part3/Chapter2" } }
  ]
}
```

`get_toc` の応答には、本則の構造ノードに `path`（`Part3/Chapter2`）を足しました。条と、附則の中のノードには付けません。附則の範囲は `suppl_index` で指すので、附則の中の章にパスを振る必要がないためです。

### 4-3. 上限は条の単位で打ち切り、続きの条番号を返す

3 つの形を比べました。

| 形 | 1 回目で得られるもの | 判断 |
|---|---|---|
| A. 入るところまで返し、続きの条番号を付ける | 条文（一部） | **採用** |
| B. 大きすぎたら `TOO_LARGE` で下位の節の候補を返す | 何も返らない | 見送り |
| C. 既定は条見出しの一覧、本文は `with_body: true` のときだけ | 目次（`get_toc` と重複） | 見送り |

A なら 1 回で条文が読めます。B は返す量が常に予測できる代わりに、章を指定した利用者が本文を一切得られません。C は `get_toc` と役割が重なります。

既定の上限は **30,000 文字**（`max_chars`、2,000〜120,000）。民法の章はほとんどが 1 回で収まり、会社法・所得税法の大きい章が 2〜3 回に分かれる量です。**条の途中では切りません**。1 条目だけは上限を超えても返します（応答が空になるのを避けるため）。

打ち切ったときの `range` は次の形です。`from_article` に `next_from_article` を渡すと続きから返します。

```jsonc
{
  "path": "Part3/Chapter2",
  "titles": ["第三編　債権", "第二章　契約"],
  "tag": "Chapter",
  "article_count": 198,
  "returned_count": 186,
  "skipped_count": 0,
  "first_article": "第521条",
  "last_article": "第684条",
  "truncated": true,
  "body_chars": 29911,
  "max_chars": 30000,
  "next_from_article": "685",
  "note": "範囲の条 198 件のうち 186 件を返しました（第521条〜第684条）。本文 29,911 文字（上限 30,000 文字）。上限で打ち切りました。続きは from_article: \"685\" を付けて同じ範囲を呼び直してください。"
}
```

Issue の完了条件「返却範囲が応答に記載される」は、この `range` と、Markdown の出典の前に置く `note` の 1 行で満たします。

### 4-4. 附則は #24 で決めた番号をそのまま範囲にする

`suppl_index` は `get_toc` の `suppl_provisions[].index`（= ローカル DB の条番号 `Suppl{index}_{条番号}`、`search_fulltext` が「附則(12) 1」と表示する番号）と同じ番号です。#24 で附則に番号を振っておいたので、#22 では新しい語彙を作らずに済みました。

条を立てず項だけで書かれた附則（消費税法に 9 本）は、条が 0 件なので範囲の本文をそのまま返し、その旨を `note` に書きます。

## 5. 実データで確かめたこと

VM から e-Gov 法令API v2 を直接引いて、実装した関数を通しました。

| 呼び出し | 結果 |
|---|---|
| `{ law_name: "民法", part: 3, chapter: 2 }` | 198 条のうち 186 条（第521条〜第684条、29,911 文字）、`next_from_article: "685"` |
| 続けて `{ …, from_article: "501" }`（第三編第一章） | 183 条のうち 39 条、`skipped_count: 144` |
| `{ law_name: "民法", chapter: 2 }` | `INVALID_ARGUMENT` + 候補 5 件 |
| `{ law_name: "会社法", part: 2, chapter: 1 }` | 81 条・29,339 文字が 1 回で収まる |
| `{ law_name: "会社法", path: "Part2/Chapter2/Section1" }` | 17 条・11,354 文字 |
| `{ law_name: "所得税法", chapter: "2の2" }` | `Part1/Chapter2_2`（法人課税信託の受託者等に関する通則）2 条 |
| `{ law_name: "労基法", chapter: 6 }` | `Chapter6`（年少者）9 条。編を持たない法令でも章だけで決まる |
| `{ law_name: "消費税法", part: 1 }` | `RANGE_NOT_FOUND`（章のみの法令に編を指定した） |
| `{ law_name: "消費税法", suppl_index: 7 }` | 条 0 件の附則。項の本文をそのまま返す |

テストは 432 件（新規 34 件）が Linux / Node 22 で通ります。`biome check` と型検査も通ります。
