### 背景

Discussion #24 の劣っている点 4 です。初回の取り込みが 6 種別で約 100 分かかります。試すコストが高く、知った人が落ちる主因だと整理しています。

同じ Discussion に「自分用でも重い」とも書いてあります。誰に向けるかを決めなくても、直す価値があります。

### いまの状態

- `--bulk-download-everything` が 6 種別すべてを入れる。約 100 分
- 種別ごとのフラグ（`--bulk-download-all` / `--bulk-download-qa` / `--bulk-download-tax-answer` / `--bulk-download-kaisei` / `--bulk-download-jimu-unei` / `--bulk-download-bunshokaitou`）はある
- 税目を絞るフラグ（`--bunsho-taxonomy` / `--tax-answer-taxonomy` / `--qa-topic`）もある
- DB が無いときはライブ取得で動く。応答は約 700ms（DB ありは約 10ms）

つまり「短く試す」ための部品はすでにあります。欠けているのは、**初めて入れた人がどれを打てばよいかが分からない**ことです。README も `--help` も、全部入りを先に書いています。

### やること

- 数分で終わる入口を 1 つ用意する。案: `--bulk-download-quickstart`（消費税基本通達 + タックスアンサーだけ、など、最初の一件に届く最小の組み合わせ）
- 実行前に、何をどれだけ取り込むか（件数の目安と所要時間の目安）を表示する
- 全部入りのコマンドは、所要時間を明記したうえで「あとから足せる」ことを README に書く
- DB が無いままでも動くこと（`source: "live"`、約 700ms）を、欠陥ではなく試用の経路として README と `--help` の先頭に書く
- `--help` の並び順を「まず試す → 必要な種別を足す → 全部入り」に変える

### 完了条件

- 初めて入れた人が、5 分以内に 1 件の通達を引けるところまで到達できる
- `--help` の先頭に、その手順が書かれている
- 全部入りの所要時間が、実行前に表示される
