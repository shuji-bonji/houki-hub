### 背景

`kuro6061/e-gov-mcp` の `follow_law_chain` / `explain_law_article` / `find_related_laws` に相当する処理がありません。「この条が指す施行令はどれか」をサーバーが解決しないため、LLM が次の `search_law` を自分で組み立てています。

### houki-hub#8（法令グラフ）との関係 — 2026-09-14 に決定

対象が重なっていても、**MCP のツールとして実装します**。理由は次のとおりです。

- RAG は Claude のサービスに入っており、自分で組むなら API 経由になる
- GraphRAG も、エンティティと関係の抽出は Claude API に頼ることになる
- MCP が出すべきなのは、LLM の判断を挟まずに引ける参照関係

そのうえで層を分けます。

| 層 | 返すもの | 作り方 |
|---|---|---|
| **本 Issue（MCP）** | 法令 XML と法令名の規則から決定論的に引ける参照。同じ入力に同じ出力 | このリポジトリのコード |
| houki-hub#8（グラフ） | 意味的な近さ、趣旨の関連、条をまたぐ要約 | Claude API による抽出 |

本 Issue の出力は houki-hub#8 の入力にもなります。重複ではなく段です。

### やること

3 つに分けます。

**1. 法令名の規則による関連付け**

- 「所得税法」から「所得税法施行令」「所得税法施行規則」を引く
- `houki-abbreviations` の逆引き（`lookupByLawId` / `lookupByLawNum`）を使う
- 名前を組み立てただけで返さない。e-Gov 側で実在を確認してから返す

**2. 条文本文からの参照抽出**

- 他法令への参照は本文に「法令名（元号○年法律第○号）」の形で入ることが多く、正規表現で取れる
- 同一法令内の参照（「第三十条第二項」「前項」「次条」）は別に扱う
- 取れたものだけを返す。取れなかったことを成功として返さない

**3. `next_actions`**

- 成功時の応答に `get_law` の呼び出しを入れ、辿り先へ 1 手で行けるようにする

### 返さないもの（応答にも明示する）

- 委任の趣旨の解釈（「この政令委任は何を意図しているか」）
- 意味的に近い条の推薦
- 参照の網羅性の保証

抽出できた範囲だけを返し、その旨を応答に書きます。判断は LLM 側に残します。family の方針（決定論で引けるものだけをサーバーが返す）に沿わせるためです。

### 完了条件

- 所得税法から施行令・施行規則が引ける（実在確認を通ったものだけ）
- ある条の本文が引用している他法令の条が、法令名と条番号の形で返る
- 抽出できた範囲であることが応答に書かれており、網羅性を主張していない
- `tools/list` の `inputSchema` に `additionalProperties: false` が入っている
