# 用語

このページは、houki-hub のサイトを初めて読む人が、ページの途中で出てくる語の意味を確かめるためのものです。
各語は 2〜3 文で説明し、詳しい説明があるページへリンクします。

## 部品の名前

| 語 | 意味 |
| --- | --- |
| **MCP** | Model Context Protocol。LLM のクライアント（Claude Desktop・Claude Code など）が外部のプログラムを「ツール」として呼ぶための規格です。houki-hub の MCP サーバーは、法令や通達を取りに行くツールをこの規格で提供します |
| **MCP サーバー** | MCP の規格で起動し、ツールを提供するプログラムです。houki-egov-mcp と houki-nta-mcp がこれにあたります |
| **Skill** | LLM が読む手順書です。実行するコードは無く、Markdown の文章そのものが指示です。houki-research Skill は「どの MCP をどの順に呼ぶか」「出典をどう書くか」「どこで注意喚起するか」を指示します（[houki-research Skill](/skills/houki-research)） |
| **plugin** | Claude Code・Cowork に Skill や MCP サーバーをまとめて入れる単位です。houki-research の plugin を入れると、依存する MCP サーバーも一緒に入ります（[導入手順](/guide/getting-started)） |
| **family（法規シリーズ）** | houki-egov-mcp・houki-nta-mcp・houki-abbreviations・houki-research Skill をまとめて指す呼び方です。同じ名前の付け方、同じエラーの形、同じ出典の書き方を共有しています（[全体構成と責務](/guide/architecture)） |
| **houki-hub** | family を束ねるリポジトリと、このサイトの名前です。実装はそれぞれ独立したリポジトリにあり、houki-hub は説明と仕様書をまとめています |

## 文書と出典

| 語 | 意味 |
| --- | --- |
| **一次資料** | 法令や通達の本文そのものです。houki-hub では、e-Gov 法令 API と国税庁サイトから取得した本文を指します。LLM の記憶や要約は一次資料ではありません |
| **法令** | 法律・政令・省令など、国民を拘束する定めです。どの語が何を含むかは法律ごとに違います（[文書の種類と拘束力](/guide/document-types#補足-法令-法規-law-が指す範囲)） |
| **通達** | 上級の行政機関が職員に出す命令です。職員は従いますが、国民と裁判所を拘束しません（[通達](/guide/document-types#通達)） |
| **出典（citation）** | 応答に含める「どこに書いてあるか」です。法令番号・条・項・号、通達番号、取得元の URL、取得日時で構成します。書き方は houki-research Skill が定めています |
| **略称** | 「消基通」「法人税法」のような、法令や通達の短い呼び方です。houki-abbreviations が正式名称と法令 ID に解決します（[houki-abbreviations](/lib/houki-abbreviations)） |
| **全角ゆらぎの正規化** | 「ＮＩＳＡ」と「NISA」、「第３０条」と「第30条」のように、全角と半角が混ざった表記を 1 つの形に揃えることです。取り込むときと検索するときの両方で同じ関数を通すので、どちらの表記で検索しても同じ結果になります |

## 応答に付く印

MCP サーバーの応答（JSON）には、本文のほかに次のフィールドが付きます。LLM が応答を説明するときの根拠になります。

| フィールド | 意味 |
| --- | --- |
| **`freshness`（鮮度）** | 取得した内容がどれだけ新しいかの判定です。取得日時と、API や索引の更新日から決めます。古いときは houki-research Skill が再取得を指示します |
| **`legal_status`** | houki-nta-mcp が通達を返すたびに付ける、拘束力の印です。`binds_citizens: false`（国民を拘束しない）、`binds_tax_office: true`（税務署の職員は従う）のように書きます（[通達](/guide/document-types#通達)） |
| **`index_status`** | houki-nta-mcp の検索結果で、その文書が国税庁の索引にまだあるかの印です。`"removed_from_index"` なら、索引から外れた文書で、現在の取扱いの根拠にはしません |
| **`source`** | 本文をどこから返したかの印です。ローカル DB から返したか、API や国税庁サイトから直接取ったか（`"api-fallback"` など）が分かります |
| **`next_actions`** | その応答の次に呼ぶとよいツールと引数の案です。たとえば通達を返したあとに「根拠の法律を houki-egov-mcp の `get_law` で引く」を案内します。`example` の `mcp` と `tool` は、次のツールの引数ではなく案内のためのものです |
| **`source_mcp_hint`** | houki-abbreviations の辞書エントリに付く、その略称をどの MCP サーバーが扱うかの印です。houki-egov-mcp に国税庁の通達の略称を渡すと、この印を見て `OUT_OF_SCOPE` を返します |
| **エラー契約** | family のどの MCP サーバーも、エラーのときは `isError: true` と `code`（`NOT_FOUND`・`OUT_OF_SCOPE` など）を同じ形で返す、という約束です。`code` の一覧は houki-research Skill の `ERROR-CODES.md` にあります |

## 仕様とその置き場所

| 語 | 意味 |
| --- | --- |
| **正典** | 「その事柄を決める文書はここ 1 つ」と定めた置き場所のことです。たとえば出典の書き方は houki-research Skill の `docs/` が正典で、ほかの場所に書いてある説明はその写しです。食い違ったときは正典が正しいものとして扱います |
| **仕様書** | 各リポジトリの `specs/current/` にある、ツールごとの「何を返すか」「何を返さないか」の約束です。このサイトの [仕様](/specs/) はそこから生成しています |
| **仕様 ID** | 仕様書の約束 1 つ 1 つに付けた識別子です。テストや Issue から「どの約束の話か」を指すために使います（[仕様書の読み方](/specs/#仕様-id)） |
| **リファレンス** | ツールごとの引数（型・必須・既定値）と、実際に呼んだときの応答の例です。MCP サーバーの `tools/list` の応答から生成しています（[リファレンス](/reference/mcp/houki-egov/)） |
| **ローカル DB** | 条文や通達の本文を手元の SQLite に取り込んだものです。作るのは任意で、無くても MCP サーバーは動きます（[ローカル DB](/guide/local-database)） |

## 線引きに関する語

| 語 | 意味 |
| --- | --- |
| **当てはめ** | 具体的な事実を法令の要件に照らして、「この場合はこうなる」と結論を出すことです。houki-hub はここまでは行いません。条文と通達を揃えて返すところまでです（[houki-hub とは](/guide/overview#しないこと)） |
| **業法の独占業務** | 弁護士法 72 条・税理士法 52 条・社労士法 27 条が、資格を持つ人だけに認めている仕事です。他人のために報酬を得て当てはめを行うことがこれにあたります（[免責事項と利用範囲](/guide/disclaimer)） |
| **資格を持つ専門家** | 弁護士・税理士・社会保険労務士など、当てはめと結論を業として行える人です。houki-hub は、質問がその領域に入ったときに相談を案内します |
